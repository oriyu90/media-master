## 1. 現状分析

### 1-1. ライブラリ（デスクトップモード）でメディアが全画面にならない

現状の関連経路:

| 場所 | 現状 |
|---|---|
| `ui/LibraryScreen.kt:394,426` | `prepareViewer(..., startFullscreen = true)` で全画面意図を渡している |
| `ViewerScreen.kt:107` | `startFullscreen = launch?.startFullscreen ?: !desktop` で初期値決定 |
| `ViewerScreen.kt:142-154` | システムバーを隠す `DisposableEffect` が **`!desktop` のときだけ**有効 |
| `ViewerScreen.kt:370-385` | 全画面ボタンは `isFullScreen` / `chromeVisible` を切り替えるだけ |
| `ui/DesktopNavigation.kt:264-322` | デスクトップシェル（サイドバー・タブ帯・フッター）が常に描画され、`NavHost` はその内側 |
| `ui/MainNavigation.kt:124-133` | デスクトップ時は MiniPlayer をシェルの上に重ねる |

原因は 2 つ。

1. **シェルが常に残る**: `isFullScreen` は「アプリ内オーバーレイを隠す」だけの
   フラグで、デスクトップのサイドバー・タブ帯・フッター・MiniPlayer は
   隠れない。したがって「タブの中で表示が広がる」以上のことが起きない。
2. **システムバーを隠さない**: `!desktop` 条件により、デスクトップでは
   ステータスバー／ナビゲーションバーが残る。

また、ライブラリから編集画面へ遷移すると、ビューアのコンポジションは
破棄されるため、フルスクリーン状態をビューア内の `remember` だけで
保持すると編集画面でシェルが戻ってしまう。

### 1-2. 透かしツールバーの上に隙間が空く

`ViewerScreen.kt:506-508` が `TopAppBar` の**外側**に
`Modifier.windowInsetsPadding(WindowInsets.safeDrawing.only(Top))` を付けて
いる。Material 3 の `TopAppBar` は `windowInsets` 引数を**Surface の内側**で
消費するため、外側の padding は「バーの背景ごと下げる」結果となり、
ステータスバー領域が透明な隙間として残る。

### 1-3. 傾き（軸）・カラー調整を中央へ戻せない

- `ui/ImageEditorScreen.kt:247-252`: X/Y/Z 傾きは `Text` + `Slider` のみで
  リセット手段がない。
- `ui/AdjustmentControls.kt:40-44`: カラーは項目選択後に `Slider` のみ。
- 既定値は `getDefaultAdjustmentValue()`（コントラスト/彩度は 1f、他は 0f）。

### 1-4. 切り抜きのアスペクト比

`ui/ImageEditorScreen.kt:255-270` の「切り抜き」タブは、実体としては
四隅ドラッグの**遠近切り抜き**のみで、矩形の切り抜き・アスペクト比固定が
存在しない。要望は「切り抜きでアスペクト比を設定」。

### 1-5. 四隅を合わせる（遠近補正）

四隅 UI は上記の切り抜きタブ内にあるが、

- プレビューの表示矩形と画像実座標が一致していない（`ContentScale.Fit` の
  レターボックスを無視して Box 全体を 0..1 とみなしている）。
- 90° 回転すると `graphicsLayer` で見た目だけ回り、保存側は
  `Bitmap.createBitmap(w, h, matrix)` で元サイズに切り取るため、
  回転と遠近の合成結果がプレビューと一致しない。
- 保存はチェックボタン時のみで、要望の「OK を押したらその場で切り取り＆変形」
  になっていない。
- 要望の配置は「変形」タブ（左右反転・90°回転の並び）。

## 2. 設計方針

### 2-1. デスクトップ没入（Immersive shell policy）

「ビューア内の全画面フラグ」と「デスクトップシェルを畳むか」を分離し、
Shell 側がルートで安全にゲートする。

新規 pure seam `ui/DesktopViewerPolicy.kt`:

```kotlin
internal fun isMediaPresentationRoute(route: String?): Boolean
// viewer/ , imageEditor/ , videoEditor/ のみ true

internal fun shouldCollapseDesktopShell(requested: Boolean, route: String?): Boolean
// requested && isMediaPresentationRoute(route)
```

- `ViewerScreen` に `onDesktopImmersiveChange: (Boolean) -> Unit = {}` を追加。
  `isFullScreen && hasTarget` を `SideEffect` で通知。
- `DesktopNavigation` に `immersive: Boolean` と `onImmersiveChange` を追加。
  `route` が非メディア系に変わったら `false` に戻す（ライブラリへ戻った時に
  シェルが確実に復帰）。
- シェルは `if (!hideShell) { Sidebar; Divider; ... }` で
  サイドバー・タブ帯・フッターを**コンポジションから外す**だけ。
  `NavHost` は同じ呼び出し位置に残すので、バックスタック・ページャ・
  ズーム状態は破棄されない。
- `MainNavigation` は同じフラグで MiniPlayer を隠す。
- システムバーの hide/show は **DesktopNavigation が所有** する
  （`hideShell` をキーにした `DisposableEffect`）。ViewerScreen の
  `onDispose` で show すると、ビューア→編集の遷移でバーが復活してしまう
  ため。タッチ側は従来どおり ViewerScreen が所有する。
- 編集画面（imageEditor / videoEditor）は「メディア提示ルート」に含め、
  ライブラリ発の全画面を維持する。エクスプローラ発
  （`startFullscreen=false`）は従来どおりタブ内表示。
- Back は従来どおり「全画面解除 → もう一度で戻る」。
- 追加でデスクトップの ESC でも全画面解除（DocumentViewer と同一挙動）。

### 2-2. ツールバーの上端一致

`TopAppBar` の外側 `windowInsetsPadding` を削除し、`windowInsets` 引数へ
`safeDrawing.only(Top + Horizontal)` を渡す。Surface（背景）は画面最上端まで
届き、タイトルやアイコンだけがカメラカットアウト／ステータスバーを避ける。
没入時はインセットが 0 になるので完全に端まで一致する。

### 2-3. 中央リセットボタン

共有コンポーザブル `SliderWithReset`（`ui/components/EditorSlider.kt`）を新設:

```
Row {
  Column(weight 1f) { label; Slider }
  IconButton(reset) { Icon(RestartAlt) }  // 48dp タップ領域
}
```

- 傾き X/Y/Z: 既定 0f。
- カラー: `getDefaultAdjustmentValue(type)`。
- 値が既に既定なら `enabled = false`（押せないことを示す）。
- contentDescription は `reset_adjustment`（5 ロケール）。
- 動画エディタの Adjust も `AdjustmentControls` 経由で自動的に恩恵を受ける。

### 2-4. 切り抜き（矩形＋アスペクト比）

`ui/editor/CropMath.kt`（JVM pure）:

```kotlin
data class CropRect(l, t, r, b)          // 0..1 正規化
enum class AspectOption(labelRes, ratio) // FREE / ORIGINAL / 1:1 / 4:3 / 3:4 / 16:9 / 9:16 / 3:2 / 2:3
fun fitAspect(current, ratio, imageAspect): CropRect
fun resizeCorner(rect, corner, dx, dy, ratio, imageAspect, minSize): CropRect
fun moveRect(rect, dx, dy): CropRect
fun isUsable(rect): Boolean
fun toPixels(rect, w, h): IntRect
```

- 画像表示は `ContentScale.Fit` の実矩形を計算し、正規化座標は
  **回転・反転後の作業ビットマップ**基準（保存パイプラインと同一）。
- オーバーレイは `Canvas` + `pointerInput`。角 4 つ（32dp 判定）でリサイズ、
  内側ドラッグで移動。比率固定時は反対角をアンカーに比率維持。
- armed でない時は消費しない（ページャ等への影響なし。エディタは専用画面）。
- 比率チップは `FilterChip` の横スクロール行。`ORIGINAL` は現在の
  ビットマップ比。
- 「リセット」で全画像。

### 2-5. 四隅合わせ（遠近補正）

`ui/editor/PerspectiveMath.kt`（JVM pure）:

```kotlin
data class Quad(tl, tr, br, bl)  // 0..1, 作業ビットマップ基準
fun defaultQuad(): Quad
fun isConvex(q): Boolean         // 交差・裏返り防止
fun isUsable(q, minArea): Boolean
fun outputSize(q, w, h): Pair<Int, Int>  // 対辺平均（最低 1px）
fun quadToDisplay(q, rect): 4 points
fun displayToQuadDelta(...)              // ドラッグ→正規化
```

UI:

- 「変形」タブに `OutlinedButton`「四隅を合わせる」を追加
  （左右反転・90°回転の隣）。押すと `perspectiveMode = true`、
  四隅は現在の画像全周にリセット。
- プレビュー上に四隅＋ガイド線＋外側減光を描画。角は 44dp タッチ領域。
- 下部に「OK」「キャンセル」「角をリセット」と、無効時の説明文。
- **OK の即時適用**: 現在の幾何（反転・傾き・回転）をフル解像度で焼き込み、
  その上で `Matrix.setPolyToPoly(src→dstRect)` を実行して新しい作業
  ビットマップにする。プレビューと完全一致。幾何パラメータは 0 に戻す
  （焼き込み済みのため）。失敗時は元のビットマップを維持し Toast。
- 凸性チェックに失敗する場合は OK を無効化（クラッシュ・破綻防止）。

### 2-6. 編集パイプラインの作り直し（プレビュー＝保存の一致）

現状は `graphicsLayer` で見た目だけ変え、保存側は別ロジックだった。
v1.14.0 では **同じ純関数** からプレビューと保存を作る。

```
source bitmap
  → (flipH, tiltX, tiltY, rotateZ)          … GeometryMath / BitmapGeometry
  → perspective quad（OK 時に焼き込み）
  → crop rect
  → color matrix
  → JPEG → MediaStore (Pictures/Edited)
```

- プレビューは長辺 ≤ 1024px の縮小コピーに同じ幾何を適用して生成
  （`Dispatchers.Default`、ジョブは最新のみ）。
- 傾き（X/Y）は `android.graphics.Camera` を廃止し、**画像長辺に比例した
  カメラ距離の純射影**（`GeometryMath.tiltProjectedCorners`）に置換。
  Camera はピクセル空間で固定距離のため、1024px プレビューと 4096px 保存で
  歪みが一致しなかった。純射影は解像度非依存で、単体テストで固定する。
- 90° 回転は**外接矩形**を計算して正しく回す（現状の見切れを修正）。
- 作業ビットマップは長辺 ≤ 4096px にサンプリングして読み込む
  （巨大画像での OOM 回避。12MP はほぼ原寸、48MP は縮小）。
- 中間 Bitmap は `recycle()`、`try/catch(OutOfMemoryError)` で元を維持。
- 保存は `Result` を返し、失敗時は Toast＋画面維持（無言で閉じない）。
- 色行列は従来の brightness/contrast/saturation を維持（互換）。

### 2-7. 互換性・安全設計

| 項目 | 対策 |
|---|---|
| 既存の全画面挙動（タッチ） | `startFullscreen` 既定は据え置き。ライブラリ/アルバムは true のまま |
| エクスプローラのタブ表示 | `startFullscreen=false` を維持。全画面ボタンで初めてシェルを畳む |
| バックスタック | NavHost の呼び出し位置を変えない（シェルの兄弟だけ条件付け） |
| 画像編集の出力先 | 従来どおり `Pictures/Edited` に新規作成（元ファイル不変） |
| 言語 | 5 ロケールに同一キーを追加（parity テストで強制） |
| RTL | 既存 `start/end` padding と `Arrangement` を使用。四隅は左右対称 |
| メモリ | 作業画像 4096 上限、プレビュー 1280、中間 recycle、OOM 捕捉 |
| 失敗時 | 読み込み/保存/遠近適用は runCatching。UI は現状維持＋Toast |

## 7. リスクと緩和

| リスク | 緩和 |
|---|---|
| シェル折り畳みで NavHost が再生成され状態消失 | 兄弟の条件付けのみ。NavHost の呼び出し位置を固定 |
| システムバーが他画面へ漏れる | `DisposableEffect` の `onDispose` で必ず show |
| 大画像で OOM | 4096 サンプリング、プレビュー 1280、recycle、OOM 捕捉 |
| 遠近の退化（線が交差） | 凸性＋面積チェック、OK 無効化 |
| 回転後に切り抜き座標がずれる | プレビューも保存も「幾何適用後ビットマップ」基準に統一 |
| 5 ロケールのキー漏れ | `LocaleStringParityTest` |
| RTL で四隅が逆 | 正規化座標（左上原点）で計算し、描画のみ LTR 座標 |
| 既存のタッチ全画面回帰 | `startFullscreen` 既定値と BackHandler を不変に保つ |

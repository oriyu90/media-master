# v2.0.0 作業計画書 — 外部アプリから渡された写真・動画のビューア

- 作成日: 2026-10-31
- 対象: `oriyu90/media-master`
- 基準版: v1.14.0 (`versionCode 23`)
- 目標版: v2.0.0 (`versionCode 24`、安定版)
- 要望: 外部（`ACTION_VIEW` / API 連携）から渡された画像をライブラリのビューアで全画面表示。
  - ライブラリ内にある画像 → そのまま前後スクロールで移動できる。
  - ライブラリ内にない画像 → 1枚だけ表示（前後移動なし）。上から下へのスワイプでビューアを閉じ、ライブラリ画面へ。

## 1. 現状分析

| 場所 | 現状 |
|---|---|
| `deeplink/DeepLinks.kt` | `ACTION_VIEW` の image/video/audio はすべて `"library"` へ。単体ファイル表示は「later phase」のコメント付き |
| `MainNavigation.kt` | `viewer/{path}` は `MediaStore` 上のパスだけを対象に `ViewerOrder.resolve` で一覧を作る |
| `ViewerScreen.kt` | `path` が `mediaState` に無いと `EmptyState`。外部 URI を受け取る口がない |
| `ViewerOrder.kt` | 外部 URI はパス照合できないため、仮に viewer へ渡しても 1 ページにもならない |

つまり「外部画像を viewer で開く」入口と、「ライブラリ内で見つかった場合だけライブラリ順にページングする」判定が未実装。

## 2. 設計

### 2-1. ルート

新規 `externalViewer/{uriString}?mime={mime}` を追加。
`DeepLinks.resolve` の `ACTION_VIEW` image/video をこのルートへ変更（audio は従来どおり `library`）。
MIME が `*/*` / null / octet-stream の送信元向けに、拡張子（jpg/png/heic/mp4/mkv…）からの推定フォールバックを追加。
ディレクトリ・文書・ZIP の既存ルートは不変。

### 2-2. 外部 URI の解決

`external/ExternalMediaInfo`（表示名・サイズ・MIME・DATA パス・MediaStore `_ID`・更新日時）を
`resolveExternalMediaInfo()` が `OpenableColumns` と MediaStore 列からベストエフォートで解決。
QUERY は全て `runCatching` で保護し、プロバイダ非対応でもクラッシュしない。
解決前は URI の最終セグメントとインテント MIME で即時表示できるフォールバックを持つ。

### 2-3. ライブラリ照合とページング

pure `matchLibraryFile()` が次の順で照合:
1. content URI 文字列の完全一致
2. 解決したファイルパス（DATA / file://）
3. MediaStore `_ID`

表示名・サイズだけの照合はしない（別ファイルを誤ってページング対象にするより、1枚表示の方が安全）。
一致した場合は `libraryMediaOrder()`（ライブラリの写真タブと同じ「除外フォルダを隠す・更新日時昇順」）を
ページャに使い、`externalMediaList()` が一致時はその一覧、不一致時は外部ファイル1件を返す。
外部ビューアがコールドスタートの最初の画面でもページングできるよう、`mediaState` が未取得成功なら
`loadAllMedia()` を一度だけ実行する（失敗時の無限リトライはしない）。

### 2-4. ビューアの振る舞い

- 外部起動は常に全画面（`isFullScreen=true`）で開始。デスクトップではシェルを畳む（`externalViewer/` を
  `DesktopViewerPolicy` のメディア提示ルートに追加）。
- ライブラリ内一致: 前後スワイプでライブラリ順に移動。削除・名前変更も通常どおり可能。
- 不一致: 1ページのみ（水平スワイプで移動しない）。削除・名前変更は非表示（外部プロバイダのファイルを
  誤って破壊しない）。共有・編集・情報・OCR は利用可能。
- 閉じる操作（戻る・ESC・上から下スワイプ・ツールバーの戻る）は、外部起動では必ず **ライブラリ画面** へ。
  通常のビューアは従来どおり `popBackStack()`。
- 一時的な URI 読み取り権限で編集画面・OCR・共有が動く（既存の content URI 経路を再利用）。

### 2-5. 安全設計

| 項目 | 対策 |
|---|---|
| 権限切れ/読み取り不能 | 画像ロードの既存エラーUI、閉じればライブラリへ |
| プロバイダ差異 | すべてのメタデータQUERYを `runCatching`、`_ID`/DATA が無くても表示可能 |
| 破壊的操作 | 外部のみのファイルは削除・名前変更を非表示。一致時のみ通常操作 |
| 状態保持 | 既存の `rememberSaveable` / ON_DESTROY の契約を維持。ルートキーは外部 URI |
| 回帰 | 通常ビューアの `ViewerOrder`・全画面・スワイプ・OCR・-dismiss は不変 |
| 言語 | 新規文言なし（既存5ロケールを再利用） |

## 4. テスト

### 単体
- 外部 URI の一致（contentUri / path / id）と不一致（名前・サイズのみ）
- ライブラリ順（画像・動画のみ、除外フォルダ非表示、更新日時昇順）
- 一致時は一覧、不一致時は1件
- MediaStore ID のパース（`123`, `image:123`, `video:123`）
- `DeepLinks` の image/video → externalViewer、audio → library、MIME 欠落の拡張子推定
- `DesktopViewerPolicy` に externalViewer
- 既存 198 件の回帰

### エミュレータ
1. コールドスタートで `content://media/.../30`（ライブラリ内）→ 全画面、タイトル、削除/名前変更あり、
   左スワイプで次の画像へ。
2. アプリ内ファイル `file://.../external_private.jpg`（ライブラリ外）→ 全画面、削除/名前変更なし、
   左スワイプで変化なし、下スワイプでライブラリ画面。
3. ライブラリ内の外部画像を閉じる/戻る → ライブラリ画面。
4. デスクトップでシェルが畳まれ、閉じると戻る。
5. FATAL 0、R8 リリースAPKでも同じ。

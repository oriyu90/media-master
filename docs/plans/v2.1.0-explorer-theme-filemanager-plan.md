# v2.1.0 作業プラン — Explorer 強化 / アクセントカラー / 標準ファイル管理アプリ化 / D&D 最適化

> 起点: v2.0.1 (versionCode 25)。ユーザー要望4件 + GUI 不整合の解消。
> 方針: 既存機能・互換性・クラッシュ安全性・メモリ安全性を崩さない最小差分。全 UI 文言は
> `values`(en) / `values-ja` / `values-zh` / `values-ar` / `values-nl` の 5 言語 parity（テストで強制）。

## 1. 現状分析（コード実測）

| 要望 | 現状 | 問題点 |
|---|---|---|
| 1 エクスプローラー: パスコピー / パスで移動 | パスをコピーする手段なし。移動は `FolderPickerDialog` をルートから辿るのみ。 | 深い階層への移動・他アプリから得たパスの貼り付け不可。 |
| 1 ダブルクリックで改名 | `combinedClickable` の onClick/onLongClick のみ。 | マウスのダブルクリックで開く（=改名不可）。 |

## 2. 設計

### 2.1 WP1 エクスプローラー（`FilesScreen.kt`, `FileViewModel.kt`, 新規 `ui/components/PathDialogs.kt`）
- 選択メニュー/コンテキストメニューに「パスをコピー」（`ClipboardManager`、`copied_to_clipboard` トースト）。
- 「パスを指定して移動」ダイアログ: 入力パスを正規化（`/sdcard` → 実ルート、`~`、末尾 `/`）、
  `File.isDirectory` 検証、自身/子孫ディレクトリ拒否（pure 関数 `PathInput` に切り出して単体テスト）。
- 移動/コピーは `FileViewModel.moveFiles/copyFiles`（複数対応・既存単一 API は委譲で維持）。
- マウス: `pointerInput` で `PointerType.Mouse` の Press を時刻差 < 400ms で判定し改名ダイアログ。
  タッチは既存の長押しメニュー（改名項目あり）を維持。
- 列: ヘッダと行で同じ `FileColumns`（weight 定数）を共有。Modified ヘッダは Modified でソート。
  区切り線は `start = 72.dp` をやめ、`ListItem` の content 幅に揃える。

### 2.2 WP2 アクセントカラー（新規 `ui/theme/AccentPalette.kt`, `Theme.kt`, `SettingsRepository`, `SettingsScreen`）
- プリセット 8 色（Amber=現行, Blue, Green, Purple, Pink, Orange, Teal, Red）+ カスタム hex 入力 + リセット。
- 生成は pure 関数 `buildAccentScheme(seed, dark): ColorScheme`。HCT 相当は使わず、
  seed の色相を HSL に変換し、**固定の明度/彩度ランプ**（現行 amber トークンと同じ明度・彩度系列）へ
  色相だけ差し替える → 既存のコントラスト保証（AA）を全色相で維持。
  - 生成後 `ensureContrast()` で onPrimary/onPrimaryContainer のコントラスト比 < 4.5 なら明度を段階調整。
  - `ThemeContrastTest` を全プリセット×昼夜で回す回帰テストを追加。
- ニュートラル（surface 系）は amber の暖色ニュートラルを維持（要望はワンポイント色）。
- 保存: `SettingsRepository.ACCENT_COLOR`（int, ARGB）。既定 = 現行 amber（互換）。
- 動的カラー既定 OFF は維持（AGENTS.md 不変条件）。

### 2.3 WP3 標準ファイル管理アプリ（`AndroidManifest.xml`, `deeplink/DeepLinks.kt`, `FilePickerScreen.kt`, `MainActivity.kt`）
- `ACTION_SEND` / `ACTION_SEND_MULTIPLE`（`*/*`）を受けて「保存先フォルダ」を選び、`ContentResolver` 経由で
  コピー保存（`SAF` 不要、`MANAGE_EXTERNAL_STORAGE` 前提の既存設計と整合）。重複名は `name (1).ext` 連番。
  pure 関数 `IncomingFiles.uniqueName()` + `SendRequest.parse()` を単体テスト。
- ピッカー: `EXTRA_ALLOW_MULTIPLE` 時は複数選択 UI + `ClipData` で複数返却（単一時は従来どおり `data`）。
  `Intent.EXTRA_STREAM` の `content://` は FileProvider で付与済み。
- 全端末安全: `MANAGE_EXTERNAL_STORAGE` 未許可端末でも、外部 URI の閲覧（VIEW）は権限画面で止めない
  （既存の権限ゲートを「外部 URI 由来のルートは許可」に緩和）。API 24-25 の `READ/WRITE_EXTERNAL_STORAGE` は従来どおり。
- `ACTION_SEND` は BROWSABLE にしない（Web から勝手に起動させない既存方針を維持）。

### 2.4 WP4 D&D 最適化（`FilesScreen.kt`, `ui/DesktopNavigation.kt`, `ui/components/DragDrop.kt` 新規）
- ドラッグ元: フォルダ・ファイル両方。`ClipData` は `text/plain` にパスを 1 件ずつ（複数選択中は選択全部）。
  `flags = DRAG_FLAG_GLOBAL`（マウス）+ `DRAG_FLAG_ACCESSIBILITY`。タッチは長押しで開始（`startDragAndDrop` の
  `dragAndDropSource` はタッチでも動くが、既存長押しメニューと競合するため `detectDragGesturesAfterLongPress` を併用）。
- ドロップ先: (a) フォルダ行/グリッドタイル、(b) サイドバーのピン/ストレージ、(c) パンくずの各セグメント。
- ドロップ時は `FileViewModel.moveFiles`（同一親なら no-op、自分自身/子孫は拒否）。
- フィードバック: ドラッグ中はカーソル/行を `primaryContainer` でハイライト、`dragAndDropTarget` の
  `onEnter/onExit` で状態管理。ドロップ成功はトースト（`moved_items`）。

### 2.5 WP5 GUI 整合
- 上記列・区切り線・i18n（`formatSize` を localized に寄せる）、`values-nl/strings_missing.xml` 削除。
- 選択ツールバー: アイコン過密（Share/Delete/Rename/Copy/Move/Sort = 6）→ Sort を `⋮` へ、Copy/Move を `⋮` へ集約。
- 空フォルダ時の `EmptyState` 追加（現状は真っ白）。

## 4. リスクと対策
- テーマ生成の色相差し替えでコントラスト崩れ → 生成関数内で比を検査し明度調整、テストで全プリセット検証。
- D&D のタッチ長押しが既存長押しメニューと競合 → 長押しメニューは「移動/コピー」を含むため、
  タッチの長押し開始は 500ms 後、指を動かした時のみドラッグ開始（静止長押しはメニュー）。
- `ACTION_SEND` の MIME が `*/*` で BROWSABLE 併記 → 併記しない（既存方針）。
- 権限ゲート緩和でファイル一覧が壊れる → 外部 URI 由来ルートのみ許可し、通常起動は従来どおり。
